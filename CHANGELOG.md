## [0.1.0] - 2026-09-14

First tagged release. The version is deliberately `0.x` rather than `1.0.0`: the API is still settling, so a minor bump may break source compatibility.

### Added

- **XCUITestKit**, a shared robustness toolkit for XCUITest suites: the wait / tap / text-entry / page-object helpers that several apps had each reinvented, plus the mitigation they were all missing — recovery from the accessibility-server failures that dominate slow-CI flakes. Link it from a **UI-test target only**: it uses the XCUI automation types, which ship with Xcode's XCTest rather than the open-source swift.org toolchain's.
- `ScaledTimeouts`: every wait in the kit scales by the `XCUITEST_TIMEOUT_MULTIPLIER` environment variable, so a slow runner is accommodated from the test plan instead of from test code. Exposes the `element` / `short` / `slowElement` / `launch` bands and `scaled(_:)` for a custom one. A present-but-malformed multiplier (non-numeric, zero, or negative) trips an `assertionFailure` rather than silently disabling scaling; unset means `1×`.
- `XCUIElement` waits and asserts: `wait`, `wait(scaledSeconds:)`, `waitFor(_:)`, `waitUntilHittable`, and `waitUntilFrameStable`, plus the asserting `assertExists` / `assertHidden` / `assertNeverAppears` — each taking an optional leading `message` appended to failure text that already names the element and the timeout.
- `XCUIElement` interaction: `forceTap`, `tapStable`, and `coordinateTapWhenFrameStable` poll the target's frame until it settles before touching it, dodging "Activation point invalid" and the hittability an iOS 26 floating bar reports while swallowing the tap. All three hold the touch for `tapHoldDuration` (0.1s), because an iOS 26 SwiftUI control drops an instantaneous synthesized tap and reports success anyway; pass `holdFor: 0` for the instantaneous gesture. `isVisible` reports whether an element is actually on screen, and `makeVisible(element:)` reveals one inside a known scroll container.
- `XCUIElement.setSwitch(to:)` and `isOn`: drive a `Switch` / checkbox / SwiftUI `Toggle` to a wanted state and report whether it got there, so a dropped press fails the test instead of silently leaving the screen disagreeing with what the test believes. `isOn` normalizes the `Int` `1` / `String` `"1"` / `Bool` `true` inconsistency in how XCUITest bridges a control's state into `value`.
- Retry helpers: `Retry.untilVerified`, `XCUIElement.tap(untilExists:)`, `tap(until:)` for a control confirmed by something other than another element appearing (a keypad key that swaps the keypad out, a control that dismisses itself), and `tap(untilExists:using:)`, which escalates through `TapStrategy` techniques (the default ladder runs activate → long press → off-center press) for a bar that swallows a plain tap. These are `async` and suspend with `Task.sleep` instead of pumping the run loop, so `await` them from an `async` test method.
- Text entry: `XCUIElement.clearAndType(_:app:…)` (iOS) clears a field and asserts the soft keyboard surfaced before typing, killing the "Neither element nor any descendant has keyboard focus" flake. The caller states what the field needs rather than the helper guessing: `replacingSelection` types over a `.selectAllOnFocus()` field's selection, `perCharacter` types one character at a time for a field backed by a self-canonicalizing formatter, `verifying` reads the value back and retries, and `doneButtonIdentifier` reaches a keyboard-accessory Done button for a `numberPad` / `decimalPad` dismissal. `commitByMovingFocus(to:)` (every platform) ends editing on a Return-less field whose binding only writes on editing-end, by moving first responder to a sibling.
- `XCUIApplication` scrolling and launch: `scrollToElement(_:direction:maxSwipes:)` scrolls the whole screen until the target clears a home-indicator-safe buffer and is hittable; `scrollIntoSafeBand(_:in:)` nudges an element by frame position clear of **both** the translucent floating nav bar and tab bar, which `isHittable` will not warn you about; `launchAndWaitUntilReady` launches and waits for a readiness element on a multiplier-scaled timeout; `disableLogStderrMirroring()` sets `OS_ACTIVITY_MODE=disable` (applied by default at launch) so a full `os_log` capture pipe cannot block the app's main thread during an accessibility snapshot.
- `XCUIApplication` queries: `descendant(id:)` finds an element of any type by accessibility identifier, and `staticText(value:)` finds a `Text` by the string it displays — SwiftUI surfaces that string as the element's `value`, not its `label`, so list cells and status lines are unreachable by a plain label subscript.
- iOS-only screen helpers: `tabButton` / `tapTab` (iPhone tab bar and iPad floating tabs), `dismissKeyboardStable(doneButtonIdentifier:)`, `scrollToTop`, and `selectPickerOption(_:in:)` for a menu-style SwiftUI `Picker`, whose options exist only while the menu is open and so cannot be queried beforehand.
- macOS-only helpers: `focusWindow(_:openingWith:modifiers:)` raises **and focuses** a window by title by re-sending its scene keyboard shortcut, which `click()` cannot guarantee when window restoration brings a multi-window app up with several feature windows overlapping; `clickMenuItem(_:in:)` drives a menu-bar command that has no keyboard shortcut, matching the item by identifier or visible title; `selectTab(_:)`, `openSettings()`, and `selectSettingsTab(_:)` drive a SwiftUI `TabView` / `Settings` scene, whose tabs render as `Button`s carrying the tab name in `title` rather than `label`.
- `SystemAlert` (iOS): `dismiss(accepting:labels:)` and `springboard`, plus `XCTestCase.addSystemAlertMonitor`, for the permission dialogs that interrupt a flow mid-test.
- `AXRecovery.run(maxAttempts:isHealthy:relaunch:action:)`: do → probe health → terminate and relaunch → retry, for the `kAXErrorServerNotFound` accessibility-server failures that no amount of waiting recovers from.
- Reusable CI for consuming apps: `ios-release.yml` turns an app's version tag into signed archives and uploads — verify, resolve the build number, archive once per platform, finish — driven entirely by the caller's Fastlane lanes, holding no Apple team, key, bundle identifier, or credential-repository name of its own. `ios-ci.yml` runs the build, unit, and UI-test lanes, with a configurable per-test execution-time allowance, an outer retry when a runner never starts, and one targeted rerun of a short failure list on a freshly erased simulator (a test killed by the execution-time allowance is never retried by `-retry-tests-on-failure`). The `setup-ios-simulator` composite action creates, boots, configures, and settles a fresh simulator, including the LaunchServices-migration gate that keeps install and launch from racing a half-booted device.
- Platform floor: iOS 16, macOS 13, watchOS 9, and visionOS 1, built with Swift 6 (tools version 6.0, language modes 5 and 6) under Approachable Concurrency. The platform-agnostic core — timeouts, waits, asserts, frame-stability taps, scrolling, retry, and recovery — works on all four; the soft-keyboard, SpringBoard, tab-bar, and picker helpers are iOS-only, and the window, menu-bar, and tab helpers are macOS-only. tvOS is intentionally unsupported: it has no coordinate/touch/swipe XCUITest surface (it is `XCUIRemote` focus-driven), so the kit's interaction helpers cannot apply.
