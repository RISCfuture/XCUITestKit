## [Unreleased]

### Added

- `XCUIApplication.clickMenuItem(_:in:)` (macOS-only): drives a menu-bar command that has no keyboard shortcut — opens the named top-level menu and clicks the item, matching the item by accessibility **identifier or title** (so a `CommandGroup`/`CommandMenu` `Button` is reachable by its visible title, trailing ellipsis and all) and taking the first match so a title duplicated in another menu doesn't throw. The menu-driven counterpart to `focusWindow`/`tapTab`.
- `XCUIApplication.selectTab(_:)`, `selectSettingsTab(_:)`, `openSettings()`, and the `settingsWindowIdentifier` constant (macOS-only): drive a SwiftUI `TabView` / `Settings` scene — the macOS counterpart to iOS `tapTab`. macOS renders `tabItem`s as `Button`s whose **`title`** carries the tab name (their `label` is empty), so a plain `buttons[name]` subscript misses them; these match `title` or `label`. `selectSettingsTab` additionally confirms the switch by waiting for the settings window's title to become the tab name — reliable where asserting tab-specific content is not (a menu-style `Picker`'s identifier never surfaces to the accessibility tree).
- `XCUIApplication.staticText(value:)`: finds a static text by the string it displays. SwiftUI surfaces a `Text`'s string as the element's **`value`**, not its `label` (which is empty), so table/list cells and status lines are found by value; scoped to `staticTexts` because an unscoped `.any` value-predicate walks the whole tree and is pathologically slow.
- `XCUIElement.isOn`: whether a `Switch`/checkbox/SwiftUI `Toggle` reads as on, normalizing the `Int` `1` / `String` `"1"` / `Bool` `true` inconsistency in how XCUITest bridges the control's state into `value`.
- **watchOS and visionOS support.** The platform-agnostic core (timeouts, waits, asserts, frame-stability taps, scrolling, retry/recovery) now builds for watchOS 10+ and visionOS 1+ alongside iOS 17+ and macOS 14+. The soft-keyboard, SpringBoard, and tab-bar helpers remain iOS-only (see **Changed**). tvOS is intentionally unsupported: it has no coordinate/touch/swipe XCUITest surface (it is `XCUIRemote` focus-driven), so the kit's interaction helpers cannot apply.
- `XCUIApplication.scrollToElement(_:direction:maxSwipes:)`: scrolls the whole screen in a given direction until the element's center clears a home-indicator-safe buffer and is hittable. Complements `makeVisible(element:)` (which reveals an element inside a known scroll container); use `scrollToElement` for whole-screen scrolling, scrolling *down*, or when the next action is a center-coordinate tap near the bottom safe area.
- Optional leading `message` on `assertExists` / `assertHidden` / `assertNeverAppears`, appended to the kit's auto-generated failure text (which already names the element and timeout).
- `clearAndType(_:app:perCharacter:replacingSelection:verifying:doneButtonIdentifier:)`: a `perCharacter` flag types one character at a time, for fields backed by a self-canonicalizing formatter (e.g. a fractional/decimal-shift `TextField(value:format:)`) where a single `typeText` burst can race the format round-trip and corrupt the buffer; `replacingSelection` types over a `.selectAllOnFocus()` field's selection instead of emptying it first; `verifying` reads the value back and retries the entry when it does not reflect the typed text (see **Fixed**); `doneButtonIdentifier` is forwarded to the closing keyboard dismissal so `numberPad`/`decimalPad` fields dismiss deterministically.
- `dismissKeyboardStable(doneButtonIdentifier:)`: an optional identifier taps a keyboard-accessory Done button first (deterministic, synchronous focus resignation — the only reliable dismissal for a `.decimalPad` with no Return key) before falling back to the nav-bar tap and swipe.
- `XCUIApplication.disableLogStderrMirroring()`: sets `OS_ACTIVITY_MODE=disable` for the launch so `os_log`'s stderr mirroring can't block the app's main thread on a full capture pipe during accessibility snapshots. `launchAndWaitUntilReady` applies it by default via a new `disablingLogStderrMirroring` parameter.
- `XCUIElement.commitByMovingFocus(to:)`: commits a `TextField(value:format:)` (whose binding only writes on editing-end) by moving first responder to a sibling element — for `numberPad`/`decimalPad` fields that have no Return key and can't be dismissed when the form fits onscreen. Available on every supported platform.
- `XCUIElement.tap(until:maxAttempts:interval:)`: force-taps and retries until a caller-supplied `condition` holds — the closure-based companion to `tap(untilExists:)` for controls confirmed by something other than another element appearing (a keypad key that swaps the keypad out and so becomes non-hittable, a control that dismisses itself). Recovers when the first tap is dropped mid-animation, which `forceTap()` followed by a single wait cannot.
- `XCUIElement.tap(untilExists:using:timeout:)`: escalates through a list of `TapStrategy` techniques (the default `.escalating` runs activate → long press → off-center press) until a confirmation element appears, for an iOS 26 "Liquid Glass" bar that swallows a plain tap. It stops early once the source element is gone (the tap already navigated) and grants a final doubled wait for a destination that renders slowly under simulator load — where `tap(untilExists:maxAttempts:timeout:)` only re-issues `forceTap()`. The `TapStrategy` enum (`.activate`, `.longPress`, `.pressOffset`) is public so callers can supply their own escalation.
- `XCUIApplication.scrollIntoSafeBand(_:in:topFraction:bottomFraction:maxAttempts:)`: nudges an element by frame position into a band clear of **both** the translucent floating nav bar and tab bar, rather than trusting `isHittable` (which is `true` even when a bar overlaps and swallows the tap). Complements `scrollToElement` (which clears only the bottom home-indicator buffer) when a center-coordinate tap must land between both bars.
- `XCUIApplication.focusWindow(_:openingWith:modifiers:timeout:)` (macOS-only): raises a window by title and gives it keyboard focus — the macOS counterpart to `tapTab`, the verb a page object uses to reach the window a flow runs in. Passing the scene's `keyboardShortcut` key re-sends the shortcut **whether or not the window is already open**, which is what makes it reliable: with window restoration on, a multi-window app relaunches with several feature windows open and overlapping, and `XCUIElement.click()` *raises* a window without giving it keyboard focus — so focus stays on whichever window came up first and a later coordinate tap lands on the wrong (occluding) window. Re-sending the scene shortcut opens the window if closed and raises **and focuses** it if open, which `click()` cannot guarantee. With no shortcut it falls back to `click()` on an already-open window.

- `XCUIElement.setSwitch(to:in:maxAttempts:)`: drives a `Switch`/checkbox/SwiftUI `Toggle` to a wanted state and reports whether it got there, so a dropped tap fails the test instead of silently leaving the screen disagreeing with what the test believes. It confirms the flip by the disappearance of the child element publishing the state being *left* (reading `value` straight back races the update), falling back to the element's own `isOn` where no such child is exposed; nudges the row clear of the translucent iOS 26 bars via `scrollIntoSafeBand` first; and holds each press long enough to register — a fifth of a second, above the cliff below which an iOS 26 toggle drops roughly a third of the presses aimed at it — lengthening the hold on each retry.
- `XCUIElement.waitUntilFrameStable(timeout:pollInterval:)`: the synchronous, non-asserting counterpart to the frame-stability wait inside `tapStable`, for a synchronous test path that wants a settled target but can carry on without one. Returns whether the frame settled. The poll cadence is exposed as `XCUIElement.framePollInterval`.
- A `holdFor` parameter on `forceTap`, `tapStable`, and `coordinateTapWhenFrameStable`, plus the `XCUIElement.tapHoldDuration` constant it defaults to. Pass `0` for the instantaneous tap these previously issued.

### Fixed

- `setSwitch` now **opens at a 0.2s hold instead of 0.1s**, landing the first press instead of losing roughly a third of them. Measured on an iOS 26 SwiftUI toggle, a 0.2s hold registers every time (25/25) while a 0.1s hold registers 64% of the time — the cliff sits between the two, and the opening hold sat immediately below it. A lost press is expensive rather than merely retried: it costs a full `ScaledTimeouts.short` (9s in a project scaling timeouts 3×) before the longer retry lands, which is the difference between ~1.9s and ~12.2s per toggle. The retry ladder itself is unchanged — holding the *same* target longer is what rescues a lost press; re-aiming at a different child or row does not.
- `scrollIntoSafeBand` now **stops as soon as a nudge fails to move the element** instead of spending its whole `maxAttempts` budget. A band edge can lie outside what the container can reach — the first rows of a form sit above `topFraction` with the list already scrolled to its top, and no amount of dragging brings them down — so the loop kept issuing drags that could not help. Those gestures are not free: each is a synthesized drag, and on a loaded runner the event synthesis they queue up is what makes a *later* tap exceed the per-test execution time allowance. The element is left where it is (still hittable, merely underlapping a bar), which is what the previous behaviour ended up doing anyway, just five gestures later.
- The reusable `ios-ci.yml` UI-test job now gives a short list of still-failing tests **one targeted rerun on a freshly erased simulator** before reporting failure, bounded by the new `ui-rescue-max-tests` input (default 3; `0` disables, and a longer failure list still fails immediately rather than costing another pass). `-retry-tests-on-failure` reruns a test that *asserted*, but a test killed by `-default-test-execution-time-allowance` records a single run and is never retried — so one hung interaction turned the whole job red with no second chance. The hang sits inside XCUITest's own pre-event quiescence wait (`_waitForQuiescenceAsPreEvent`), which can wait indefinitely for an app-idle notification that a CPU-starved runner drops, with the app itself parked idle in its run loop; it does not reproduce on a healthy machine, so rerunning it is the only available remedy. The rerun's xcresult is uploaded alongside the original.
- `forceTap`, `tapStable`, and `coordinateTapWhenFrameStable` now **hold the touch down briefly instead of tapping instantaneously**, fixing iOS 26 SwiftUI `Toggle`s that ignored every one of them. All three bottom out in a synthesized `XCUICoordinate` tap, whose touch goes down and up in the same instant; an iOS 26 switch drops it, and the gesture reports success anyway — so a test carried on against a control that kept its old value. This is what made a coordinate tap look like it "cannot toggle a SwiftUI switch on iOS 26"; the coordinate was never the problem, the instantaneous touch was.
- `clearAndType` **no longer guesses how a field wants to be filled**. It typed over the on-focus selection on the first attempt and read the value back on every one, and both are right for some fields and wrong for others: a field with no on-focus selection is *appended to* rather than replaced, while emptying a `.selectAllOnFocus()` field first leaves a digit of the old value for the new one to land against. The read-back that was meant to catch either matched digit-free text by *substring*, so text appended to what the field already held passed as committed — and where it did fire, it could not tell a good entry from a field that displays something other than what was typed, so a unit-converting field had its committed value cleared by the retry. Both are now the caller's to state (`replacingSelection`, `verifying`), defaulting to the behaviour a plain field needs. Measured across four apps on iPhone 17 Pro and iPad Pro 13-inch, iOS 26.5: IP-Inbound from 9 iPhone and 19 iPad failures to none, SF50-TOLD held at none by stating what its fields want.
- `clearAndType` **re-takes first responder when the caret tap misses the field**. Clearing puts the caret after the last character with a tap at the field's right edge, and that tap can land outside the editable area — on a unit label or a stepper sharing the row — resigning first responder, so the `typeText` after it dispatched into a window with none and failed outright with "Neither element nor any descendant has keyboard focus" (29 of SF50-TOLD's 47 iPhone UI tests). Both behaviours are needed: a field whose caret the tap repositions cannot be cleared without it, while a field the tap misses cannot be typed into after it.
- `dismissKeyboardStable` **waits the keyboard out again rather than judging a gesture by whether focus left**. Judging by focus is cheaper on a screen that ignores the gesture, but it stopped ending the edit at all on the screens that matter most — those whose fields write their binding only when editing ends — so a `TextField(value:format:)` kept the value it started with and every test reading it back failed.

### Changed

- **Behaviour:** `forceTap`, `tapStable`, and `coordinateTapWhenFrameStable` hold each touch for `XCUIElement.tapHoldDuration` (0.1s) by default rather than tapping instantaneously. Every call site keeps compiling; taps land where they previously could be dropped, at the cost of a tenth of a second each. Pass `holdFor: 0` to restore the old gesture.
- The soft-keyboard, SpringBoard, and tab-bar helpers — `clearAndType`, `dismissKeyboardStable`, `scrollToTop`, `tabButton`/`tapTab`, `SystemAlert.dismiss` / `SystemAlert.springboard`, and `XCTestCase.addSystemAlertMonitor` — are now compiled `#if os(iOS)`, because they depend on a soft keyboard, SpringBoard, or the UIKit tab-bar idiom that the other platforms lack. (`SystemAlert.dismiss`/`springboard` were already iOS-gated; the rest are newly scoped.) `commitByMovingFocus` moved to its own file so it stays available everywhere.
- The reusable `ios-ci.yml` UI-test job raises `-default-test-execution-time-allowance` from 240s to 420s. The heaviest UI tests (e.g. a double-launch model comparison) run ~200s on a healthy CI simulator, leaving no margin under 240s for accessibility-server/runner slowdowns; genuine hangs remain bounded by the job-level `timeout-minutes`.
- **Breaking:** `ScaledTimeouts` now reads only the generic `XCUITEST_TIMEOUT_MULTIPLIER` environment variable. The legacy per-app fallbacks (`FART_UI_TIMEOUT_MULTIPLIER`, `SF50_UI_TEST_TIMEOUT_MULTIPLIER`) have been removed; rename them to `XCUITEST_TIMEOUT_MULTIPLIER` in consuming test plans. The `multiplierEnvVarNames` array is replaced by the singular `multiplierEnvironmentVariableName` constant.
- **Breaking:** `maxAttempts` parameters (`AXRecovery.run`, `Retry.untilVerified`, `XCUIElement.tap(untilExists:)`, `XCUIElement.makeVisible`) are now `UInt` instead of `Int`. Integer literals are unaffected; callers passing an `Int` variable must convert it.
- A present-but-malformed `XCUITEST_TIMEOUT_MULTIPLIER` (non-numeric, zero, or negative) now triggers an `assertionFailure` instead of silently disabling scaling. An unset variable still defaults to `1×`.
- **Breaking:** the retry/poll helpers are now `async` and suspend with `Task.sleep` instead of pumping the run loop with `RunLoop.current.run(until:)`. `Retry.untilVerified`, `XCUIElement.tap(untilExists:maxAttempts:timeout:)`, `XCUIElement.tap(until:maxAttempts:interval:)`, `XCUIElement.tapStable(timeout:file:line:)`, `XCUIElement.coordinateTapWhenFrameStable(timeout:file:line:)`, and `SystemAlert.dismiss(accepting:labels:timeout:)` must now be `await`ed. The `action`/`until` closures of `Retry.untilVerified` and `XCUIElement.tap(until:)` are now `async`, so you can `await` other kit helpers inside them; existing synchronous closures keep compiling unchanged. Call sites move into `async` test methods, which already run on `@MainActor`. `AXRecovery.run` is unchanged — it never slept, so it stays synchronous.
- Adopted Swift's Approachable Concurrency: the package builds with the `NonisolatedNonsendingByDefault` and `InferIsolatedConformances` upcoming-feature flags.

## [1.0.0] - 2026-05-29

### Added

- Initial release of XCUITestKit
- `ScaledTimeouts`: CI-scalable UI-test timeouts driven by an environment-variable multiplier
- `XCUIElement` wait helpers: `wait`, `waitFor`, `waitUntilHittable`, `assertExists`, `assertHidden`, `assertNeverAppears`
- `XCUIElement` interaction helpers: `forceTap`, `tapStable`, `coordinateTapWhenFrameStable`, `isVisible`, `makeVisible`
- `XCUIElement.clearAndType`: clears and types text, asserting the soft keyboard surfaced first, with an iPad Cmd+A select-all fallback
- `XCUIApplication` helpers: `tabButton`, `tapTab`, `dismissKeyboardStable`, `scrollToTop`, `launchAndWaitUntilReady`
- `AXRecovery`: do → probe → relaunch → retry recovery for accessibility-server failures (`kAXErrorServerNotFound`)
- `setup-ios-simulator` composite action for hardened simulator setup in CI
- Swift 6 concurrency support
